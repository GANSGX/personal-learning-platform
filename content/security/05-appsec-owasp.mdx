## Что

Безопасность приложений (Application Security, AppSec) — совокупность процессов, инструментов и практик защиты программного кода и API на всех стадиях жизненного цикла разработки (Secure SDLC). Международный проект OWASP Top 10 публикует регулярный консенсусный отчет о самых опасных уязвимостях веб-приложений.

## Зачем

Большинство успешных атак на компании начинаются с эксплуатации уязвимостей в прикладном коде публичных веб-сервисов и API (инъекции, ошибки контроля доступа, SSRF). Устранение дефектов безопасности в коде до релиза обходится в десятки раз дешевле ликвидации последствий утечек.

## Как это работает

Ключевые категории уязвимостей и меры защиты:

1. **Broken Access Control (Нарушение контроля доступа)**: принудительная проверка прав владельца на бэкенде для каждого запроса; запрет прямого использования ID объектов из параметров URL без проверки сессии.
2. **Cryptographic Failures**: использование TLS 1.3, запрет устаревших шифров, защита данных при передаче и хранении.
3. **Injections (SQL, Command, LDAP)**: параметризованные запросы (Prepared Statements, ORM), строгая валидация и типизация входящих данных (Zod/Pydantic).
4. **Security Misconfiguration**: отключение дебаг-режимов, изменение стандартных паролей, установка защитных HTTP-заголовков (CSP, HSTS, X-Frame-Options).
5. **SSRF (Server-Side Request Forgery)**: белые списки разрешенных адресов для исходящих HTTP-запросов бэкенда, изоляция metadata-сервисов облака (`169.254.169.254`).
