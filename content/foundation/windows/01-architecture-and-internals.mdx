## Что

Операционная система Windows NT (лежащая в основе всех современных версий Windows 10, 11 и Windows Server) построена на базе модульной гибридной архитектуры с четким разделением на пользовательский режим (User Mode / Ring 3) и режим ядра (Kernel Mode / Ring 0).

Архитектура ядра Windows включает в себя:

- **Hardware Abstraction Layer (HAL)**: низкоуровневый слой аппаратных абстракций, скрывающий различия материнских плат, таймеров и контроллеров прерываний (APIC/PIC);
- **Kernel (Ядро)**: низкоуровневый планировщик потоков, синхронизация и диспетчеризация прерываний;
- **Executive (Исполнительная подсистема)**: набор базовых системных менеджеров (Object Manager, Process Manager, Virtual Memory Manager, I/O Manager, Security Reference Monitor);
- **Подсистемы пользовательского режима (User-Mode Subsystems)**: среда окружения для запуска приложений (ключевая подсистема Win32, процессы `csrss.exe`, `lsass.exe`, `smss.exe`).

## Зачем

Понимание внутреннего устройства Windows критично для системных администраторов корпоративных сред, инженеров кибербезопасности (Blue Team и DFIR) и специалистов технической поддержки. Корпоративный сектор во всем мире опирается на Windows Server и Active Directory для управления учетными записями, рабочими станциями и критическими бизнес-приложениями.

Без понимания архитектуры Win32, диспетчера объектов и механизмов взаимодействия процессов невозможно эффективно диагностировать системные сбои (BSOD), профилировать утечки дескрипторов (Handles) и памяти, а также анализировать векторы атак злоумышленников, злоупотребляющих системными API (Process Injection, DLL Hijacking).

## Как это работает

1. **Диспетчер объектов (Object Manager)**:
   В Windows практически любой системный ресурс — процесс, поток, файл, ключ реестра, секция разделяемой памяти, мьютекс — представляется в виде универсального «объекта» (Object).
   - Потоки в User Mode никогда не обращаются к объектам напрямую, а получают числовой дескриптор `HANDLE` из таблицы дескрипторов процесса;
   - Security Reference Monitor (SRM) проверяет токен безопасности вызывающего потока и список контроля доступа (DACL) объекта при каждом открытии дескриптора.

2. **Ключевые системные процессы**:
   - `smss.exe` (Session Manager): самый первый пользовательский процесс, инициализирующий переменные окружения, страничные файлы и сессии;
   - `csrss.exe` (Client/Server Runtime Subsystem): обеспечивает работу консольных окон и создание/завершение процессов;
   - `winlogon.exe` и `lsass.exe` (Local Security Authority Subsystem Service): отвечают за аутентификацию пользователей, генерацию токенов доступа и хранение учетных данных;
   - `services.exe` (Service Control Manager): управляет жизненным циклом фоновых служб Windows (аналог systemd в Linux).

3. **Инструменты исследования ядра**:
   Набор утилит Sysinternals (созданный Марком Руссиновичем) является золотым стандартом исследования внутренностей Windows: `Process Explorer` (глубокий анализ дерева процессов, дескрипторов и загруженных DLL), `Process Monitor` (перехват файловой, сетевой активности и обращений к реестру в реальном времени).
