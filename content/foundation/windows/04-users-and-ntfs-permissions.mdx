## Что

Модель безопасности Windows опирается на строгую идентификацию субъектов (пользователей, компьютеров, сервисов) с помощью уникальных числовых идентификаторов безопасности — `SID` (Security Identifier), выдачу маркеров доступа — `Access Tokens`, и гранулярное разграничение прав доступа к объектам файловой системы `NTFS` через списки контроля доступа — `ACL` (Access Control Lists).

В файловой системе NTFS каждый файл и каталог обладает дескриптором безопасности (Security Descriptor), содержащим:

- Владельца объекта (Owner SID);
- Дискреционный список контроля доступа (`DACL`): определяет, каким субъектам разрешены или запрещены конкретные операции (чтение, запись, выполнение, удаление, смена прав);
- Системный список контроля доступа (`SACL`): регламентирует политики аудита успешных и неудачных попыток доступа к объекту с записью в системный журнал безопасности (Security Event Log).

## Зачем

Безопасность корпоративной информации базируется на принципе наименьших привилегий (Principle of Least Privilege). Неправильная конфигурация прав доступа к сетевым папкам (SMB/CIFS-шарам) и локальным каталогам NTFS — одна из самых распространенных уязвимостей, приводящая к несанкционированному доступу к конфиденциальным базам данных, утечке финансовой отчетности и горизонтальному перемещению злоумышленников по сети (Lateral Movement).

Понимание того, как вычисляются эффективные права доступа (Effective Access Permissions), как работают механизмы наследования (Inheritance) и явного запрета (Deny ACE), является фундаментальным навыком любого администратора Windows Server и специалиста по защите информации.

## Как это работает

1. **Идентификаторы безопасности (SID) и токены (Access Tokens)**:
   - Имена пользователей (например, `Administrator`) — это лишь человекочитаемые метки. Система оперирует неизменными SID формата `S-1-5-21-...-500`;
   - При успешном входе пользователя процесс `lsass.exe` формирует `Access Token`, содержащий SID пользователя, список SID всех групп, в которых он состоит, и перечень системных привилегий (User Privileges, например `SeBackupPrivilege`, `SeDebugPrivilege`);
   - Все дочерние процессы, запускаемые пользователем, наследуют копию его маркера доступа.

2. **Структура ACL (DACL и ACE)**:
   Список DACL состоит из отдельных записей контроля доступа — `ACE` (Access Control Entries). Каждая запись содержит:
   - Тип: `Access Allowed` (разрешить) или `Access Denied` (запретить);
   - SID субъекта;
   - Маску прав (Read, Write, Execute, Delete, Full Control, Modify).

3. **Правила вычисления эффективных прав**:
   - **Явный запрет важнее любого разрешения**: если в DACL для пользователя или любой из его групп найдена запись `Deny`, доступ к данному действию немедленно блокируется;
   - **Явные права имеют приоритет над унаследованными (Explicit > Inherited)**;
   - **Права групп суммируются**: если группа А дает `Read`, а группа Б дает `Write`, пользователь получает `Read + Write` (при отсутствии явного `Deny`);
   - При конфликте прав сетевой папки (Share Permissions) и прав файловой системы (NTFS Permissions) действует **наиболее строгое** ограничение.

4. **Управление правами через PowerShell и утилиту icacls**:

   ```powershell
   # Просмотр списка доступа каталога
   Get-Acl -Path "C:\CorporateData" | Format-List
   # Использование проверенной системной утилиты icacls
   icacls "C:\CorporateData" /grant "Domain Users":(OI)(CI)R /inheritance:e
   ```
