## Что

Active Directory Domain Services (AD DS) — распределенная служба каталогов корпоративного уровня, разработанная Microsoft для централизованного управления учетными записями пользователей, компьютеров, серверов, групп безопасности, политик и ресурсов в корпоративной сети. Вместо локального администрирования каждого отдельного компьютера создается единый доверенный периметр — **Домен Active Directory** (AD Domain).

Сервер, хранящий базу данных службы каталогов и аутентифицирующий пользователей, называется **контроллером домена** (Domain Controller, DC). База данных каталога хранится в файле `ntds.dit` (на базе транзакционной технологии ESE / Extensible Storage Engine) и многосторонне реплицируется (Multi-Master Replication) между всеми контроллерами домена в сети.

## Зачем

В компании с десятками, сотнями или тысячами сотрудников невозможно вручную заводить учетные записи и пароли на каждом рабочем компьютере или сервере. Active Directory решает задачу построения единого центра идентификации и аутентификации (Identity & Access Management / IAM):

- **Единая точка входа (Single Sign-On, SSO)**: пользователь однократно вводит доменные учетные данные при включении ПК и получает защищенный доступ к корпоративной почте Exchange, сетевым папкам, внутренним порталам и базам данных;
- **Централизованный отзыв доступа**: при увольнении сотрудника достаточно отключить его учетную запись на контроллере домена, чтобы мгновенно заблокировать доступ ко всем серверам и корпоративным сервисам;
- Стандарт де-факто в мировой IT-инфраструктуре: практически любая корпоративная система (VPN-шлюзы, прокси-серверы, гипервизоры VMware/Proxmox, SIEM, облачные платформы) интегрируется с AD через протоколы LDAP/Kerberos или федерации (ADFS/Entra ID).

## Как это работает

Active Directory опирается на связку фундаментальных сетевых протоколов:

1. **DNS (Domain Name System) — кровеносная система AD**:
   Контроллеры домена публикуют в DNS специальные сервисные ресурсные записи `SRV` (например, `_ldap._tcp.dc._msdcs.company.local`), с помощью которых компьютеры клиентов находят ближайший доступный контроллер домена. Без исправного DNS доменная среда не функционирует.

2. **Протокол аутентификации Kerberos v5**:
   Основной защищенный протокол аутентификации в Active Directory (вытеснивший устаревший NTLM). Kerberos использует систему криптографических билетов (Tickets) без передачи паролей по сети:
   - Клиент обращается к службе KDC (Key Distribution Center) на контроллере домена и получает билет на получение билетов (`TGT`, Ticket Granting Ticket), зашифрованный на ключе доменной учетной записи `krbtgt`;
   - При обращении к целевому серверу (например, к файловому серверу) клиент предъявляет TGT и запрашивает сервисный билет (`TGS`, Ticket Granting Service), зашифрованный на секретном ключе сервиса (SPN, Service Principal Name);
   - Сервер валидирует TGS локально, не запрашивая контроллер домена, что обеспечивает высокую производительность и масштабируемость.

3. **Протокол LDAP / LDAPS (Lightweight Directory Access Protocol)**:
   Используется для поиска, запроса и модификации объектов в дереве каталога (порты TCP 389 для открытого LDAP и TCP 636 для шифрованного TLS-соединения LDAPS). Иерархия объектов задается с помощью Distinguished Names (DN), например: `CN=Ivan Ivanov,OU=Developers,OU=IT,DC=company,DC=local`.

4. **Управление через модуль Active Directory в PowerShell**:
   ```powershell
   # Поиск учетной записи пользователя в домене
   Get-ADUser -Identity "i.ivanov" -Properties MemberOf, Department, Enabled
   # Создание нового доменного пользователя
   New-ADUser -Name "Petr Petrov" -SamAccountName "p.petrov" -UserPrincipalName "p.petrov@company.local" -Enabled $true
   ```
