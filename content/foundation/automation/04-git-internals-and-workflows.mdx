## Что

Git — распределенная система управления версиями (VCS), хранящая историю изменений проекта в виде направленного ациклического графа (DAG) неизменяемых объектов с криптографической адресацией по SHA-1/SHA-256 хэшам.

## Зачем

Инфраструктура как код (Infrastructure as Code, IaC) и конфигурации сервисов хранятся в Git. Без понимания разницы между merge и rebase, работы состояния detached HEAD и устройства Git Hooks невозможно организовать надежные процессы непрерывной интеграции (CI/CD) и командной разработки.

## Как это работает

База данных Git (`.git/objects/`) хранит четыре типа объектов: `blob` (содержимое файла), `tree` (директория со списком имен и прав), `commit` (указатель на tree, авторов, дату, сообщение и родителей) и `tag`. Ветка — это просто легковесный текстовый указатель на коммит в `.git/refs/heads/`. Автоматизация контроля качества перед коммитом и пушем реализуется через клиентские хуки (pre-commit, commit-msg), управляемые инструментами вроде Lefthook или Husky.

## Контрольная точка

Объясните внутреннюю разницу между операциями `git merge` и `git rebase` с точки зрения структуры графа коммитов, и почему опасен rebase веток, уже опубликованных в общий удаленный репозиторий.
