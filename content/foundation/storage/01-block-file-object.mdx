## Что

Инфраструктурные системы хранения классифицируются на три парадигмы: блочные накопители (Block Storage: SSD/HDD, EBS, SAN), сетевые файловые системы (File Storage: NFS, SMB, EFS) и распределенные объектные хранилища (Object Storage: Amazon S3, MinIO, Ceph).

## Зачем

Попытка хранить реляционную базу данных в объектном хранилище или сохранять миллионы медиафайлов пользователей на локальный блочный диск сервера быстро приводит к катастрофе по стоимости, производительности или целостности данных. Инженер должен выбирать подходящий класс хранилища под конкретную нагрузку.

## Как это работает

Блочное хранилище предоставляет ОС массив сырых блоков байтов фиксированного размера (чрезвычайно низкая задержка, высокая производительность IOPS, поддержка произвольного чтения/записи, монтируется к одному серверу). Файловое хранилище разделяет иерархическое дерево каталогов по сети между несколькими серверами (POSIX, блокировки файлов). Объектное хранилище оперирует плоским пространством объектов с ключами и метаданными, доступных по HTTP REST API (GET/PUT/DELETE), обеспечивая почти бесконечную масштабируемость и надежность при минимальной стоимости за гигабайт.

## Контрольная точка

Сравните блочное хранилище (Block Storage) и объектное (Object Storage) по критериям задержки доступа (latency), протокола взаимодействия (NVMe/SCSI vs HTTP) и возможности частичной модификации файла на месте.
