## Что

Интеграционный экзамен объединяет все ключевые разделы фундаментального трека (Сети, Операционные системы, Linux, Системное администрирование, Web-технологии, Базы данных и Автоматизацию) в единый практический проект развертывания трехузлового инфраструктурного стенда.

## Зачем

Изучение изолированных компонентов без сборки в единую систему порождает иллюзию компетентности: инженер может знать команды `systemctl` или флаги `iptables`, но теряется при необходимости связать шлюз с двумя подсетями, пробросить SSH ProxyJump, ограничить права доступа к базе данных и настроить TLS-терминацию в связке с обратным прокси. Интеграционный проект формирует целостное системное мышление.

## Как это работает

Экзаменационный стенд состоит из трех виртуальных машин:

1. **Шлюз (Gateway / Bastion)**: имеет внешний сетевой интерфейс и изолированный внутренний интерфейс LAN (10.0.0.1/24). На нем включен IP forwarding, настроен NAT (маскарадинг) и межсетевой экран (nftables/ufw). Доступ к внутренним хостам осуществляется через SSH ProxyJump с аутентификацией исключительно по публичным ключам.
2. **Web-сервер (Web VM)**: находится во внутреннем сетевом сегменте (10.0.0.10). Запускает фоновый демон приложения под управлением systemd и Nginx в качестве reverse proxy с TLS-шифрованием, перенаправляющий HTTP-запросы и проксирующий клиентские заголовки.
3. **Сервер базы данных (DB VM)**: изолирован во внутренней сети (10.0.0.20) без прямого внешнего доступа. PostgreSQL слушает только внутренний IP и принимает соединения по паролю с алгоритмом SCRAM-SHA-256 исключительно от Web VM (`pg_hba.conf`). Регулярный бэкап данных автоматизирован bash-скриптом по cron.

## Контрольная точка

Опишите последовательность шагов и правила сетевой фильтрации (firewall), гарантирующие, что сервер базы данных (10.0.0.20) полностью изолирован от внешнего мира и принимает TCP-соединения на порт 5432 только от Web VM (10.0.0.10)?
