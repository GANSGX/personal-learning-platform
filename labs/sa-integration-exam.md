## Цель работы

Интегрировать все знания фундаментального блока (Сети, Linux, Системное администрирование, Web-стек, Хранилища и Автоматизацию) в комплексный практический проект. Вы построите реальную трехузловую инфраструктуру, аналогичную продакшен-архитектуре сервиса.

## Топология сети

```text
                            [Admin / Client]
                                   │
                              SSH / HTTPS
                                   ▼
                          [Gateway / Bastion]
                        (WAN: DHCP / LAN: 10.0.0.1)
                                   │
               ┌───────────────────┴───────────────────┐
               │                                       │
               ▼                                       ▼
      [Web VM: Nginx + App]                  [DB VM: PostgreSQL]
          (10.0.0.10)                            (10.0.0.20)
```

## Чеклист выполнения

1. **Создание и адресация виртуальных машин**:
   - `Gateway`: интерфейс 1 подключен к внешней сети (Bridged/NAT), интерфейс 2 подключен к внутренней изолированной сети (Host-Only/Internal Network) с адресом `10.0.0.1/24`.
   - `Web VM`: один интерфейс во внутренней сети с адресом `10.0.0.10/24`, шлюз по умолчанию `10.0.0.1`.
   - `DB VM`: один интерфейс во внутренней сети с адресом `10.0.0.20/24`, шлюз по умолчанию `10.0.0.1`.

2. **Маршрутизация и NAT**:
   - На `Gateway` активируйте форвардинг пакетов: `net.ipv4.ip_forward = 1` в `/etc/sysctl.d/99-sysctl.conf`.
   - Настройте маскарадинг исходящего трафика во внешнюю сеть через `iptables` / `nftables` / `ufw`.
   - Проверьте доступность интернета с `Web VM` и `DB VM` через шлюз.

3. **Защита доступа (SSH & Users)**:
   - Создайте непривилегированного пользователя с `sudo` на всех машинах.
   - Сгенерируйте и скопируйте ключи `ssh-keygen -t ed25519`.
   - В `/etc/ssh/sshd_config` установите `PasswordAuthentication no`, `PermitRootLogin no`.
   - Настройте SSH ProxyJump (`ssh -J user@gateway user@10.0.0.10`) для прямого доступа к внутренним хостам.

4. **База данных (PostgreSQL)**:
   - Установите PostgreSQL на `DB VM`.
   - Сконфигурируйте `listen_addresses = '10.0.0.20'` в `postgresql.conf`.
   - В `pg_hba.conf` добавьте разрешение: `host app_db app_user 10.0.0.10/32 scram-sha-256`.
   - Убедитесь, что прямого доступа из внешней сети к базе данных нет.

5. **Веб-сервис и Nginx**:
   - Разверните REST API или микросервис на Node.js/Python/Go на `Web VM`.
   - Создайте `/etc/systemd/system/myapp.service` с параметрами `Restart=always` и запуском от непривилегированного пользователя.
   - Сконфигурируйте Nginx как reverse proxy, перенаправляющий входящие запросы на локальный порт сервиса (`proxy_pass http://127.0.0.1:8080`).
   - Сгенерируйте самоподписанный TLS-сертификат или используйте локальный CA и настройте HTTPS (`listen 443 ssl`).

6. **Резервное копирование и автоматизация**:
   - Напишите скрипт `/opt/scripts/backup-db.sh` на `DB VM`, выполняющий `pg_dump` с сжатием gzip и датой в имени файла.
   - Реализуйте ротацию: удаление копий старше 7 дней (`find /backup -type f -mtime +7 -delete`).
   - Настройте cron-задачу для запуска резервного копирования каждую полночь.

7. **Финальное тестирование**:
   - Проверьте доступность веб-страницы по HTTPS.
   - Проверьте успешное сохранение и чтение данных приложением из PostgreSQL.
   - Перезагрузите любую из машин и убедитесь, что все сервисы корректно восстанавливаются самостоятельно.
